# Fuzzer regressions

Inputs on which `baker_parse_fuzzer` once found a bug, one file each (`*.bin`, raw
bytes). The data-layer tests run the fuzz property over every file here.

| File | Bug |
|------|-----|
| `bom_inside_symbol.bin` | A symbol starting with UTF-8 BOM bytes was printed bare at the very start of a file, where the reparse skipped the BOM. |
| `bom_symbol_with_quotes.bin` | The first fix (quoting such symbols) broke bare atoms that also contain `'`. Final fix: `to_dta` never begins with BOM bytes; it adds a leading space. |
| `quoted_remove_symbol.bin` | A quoted `'#remove'` outside a key's only value was printed bare, where the reparse refused it. Fix: `#remove` is bare only in the slot where the parser takes it. |
| `symbols_hash_alike.bin` | The symbols `''` and `'\x01'` had one name hash, and the cache write refused them. Fix: the checksum folds the length in after the bytes. |
| `bare_remove_marker.bin` | The harness read every literal token alone, and `(key #remove)`'s marker reads only in that slot, so the harness refused a tree the parser and printer handle. Fix: the harness skips the marker's token. |
| `macro_sharing_budget.bin` | Three nested macros make a tree of about 82,000 nodes from 164 bytes. The first read counts each use once and stays under the harness session's 65,536-node limit, but the print spells every node, so its reread passed the limit; the harness skipped only trees over 100,000. Fix: the harness skips a tree larger than the session's own node limit. |
| `origin_first_form.bin` | A root whose first form is `(origin "...")` held as data (a second origin after the file's own) prints as a declaration the reader consumes, so the print round trip loses it: a tree today's text cannot spell. Found by libFuzzer on the indent-lines branch; it reproduces on main. Fix: the harness skipped the print round trip for such a tree; since rows the printer writes the form as a row, and the harness skips only a top level that repeats a tag, which a file of rows cannot hold. Since #origin and #pack, the forms are data, the printer writes them as they are, and the harness skips nothing for them. |
| `lookup_meta_in_slot_zero.bin` | The lookup fuzzer's: in an untagged array, `((@range 0 10) (@ssmall 1))`, slot 0 holds metadata's tag, which the metadata boundary never names, and a sorted array's binary search for `@range` began at the boundary, so it found nothing where the linear scan found slot 0. Fix: the sorted search covers the whole array, ordered as the sort orders it. A file named `lookup_` is also held to the lookup harness. |
| `row_first_form_pack.bin` | `(/pack ...)` as a file's first form is a row and so data, which the printer wrote nested, where the reparse took it as a pack declaration. Fix: a first form a reader would take as a declaration is printed as a row. Since #origin and #pack, the forms are data, the printer writes them as they are, and the harness skips nothing for them. |
| `origin_repeated_tags.bin` | A data `(origin "...")` first form prints as a row, but not when the top level repeats a tag, where the file could not hold one: then it prints as the declaration text cannot spell. Fix: the harness skips that tree. Since #origin and #pack, the forms are data, the printer writes them as they are, and the harness skips nothing for them. |
| `quoted_layer_verbs.bin` | Seeds the property with the layer verbs: a quoted `'#append'` in a verb's slot is the verb and prints bare, one elsewhere prints quoted, and a verb's row carries metadata. Each verb's token reads only in its slot, so the harness skips it as it skips `#remove`'s. |
| `verb_rows.bin` | The verbs spelled in rows: a key's `#append` and `#drop` rows stay apart, in order, where its other rows fold. |
| `hash_symbols.bin` | Seeds the property with `#` tokens: `#` opens a directive only before a letter, so a lone `#`, `#1` and `#00aa00` are symbols the reader takes and the printer writes bare, and `'#x1'` prints quoted. |
| `declarations.bin` | Seeds the property with the directives: `#pack`, `#origin` and `#shape` read their one form into the session and leave the tree, and the forms that declared by position, `(pack ...)`, `(origin "...")` and `(shapes ...)`, are data the printer writes back as they are. |
